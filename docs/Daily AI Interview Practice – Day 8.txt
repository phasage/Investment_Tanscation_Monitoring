### Part 1. AI vs ML vs Deep Learning vs Generative AI

This is one of the most frequently asked questions in AI interviews.

### 1\. What is Artificial Intelligence?

Artificial Intelligence (AI) is a broad field of computer science that focuses on building systems capable of performing tasks that typically require human intelligence.

Examples:

* Understanding human language.

* Recognizing images.

* Making predictions.

* Identifying unusual patterns.

* Generating content.

* Answering questions.

For example, imagine an investment management application.

You want a system that can:

* Read portfolio manager emails.

* Understand buy/sell instructions.

* Extract investment information.

* Identify missing details.

* Prepare structured JSON.

* Send the information to your existing .NET API.

This is an example of how AI can enhance an existing enterprise application.

### 2\. What is Machine Learning?

Machine Learning is a subset of AI.

It allows computers to learn patterns from historical data and use those patterns to make predictions.

Example:

You have 100,000 historical financial transactions.

You train an ML model to predict whether a new transaction requires investigation.

The model learns from historical examples.

Common algorithms:

* Logistic Regression.

* Decision Trees.

* Random Forest.

* K-Means.

These are the traditional ML algorithms you studied in previous lessons.

### 3\. What is Deep Learning?

Deep Learning is a subset of Machine Learning that uses artificial neural networks with multiple layers.

It is especially useful for learning complex patterns in large datasets.

Examples:

* Speech recognition.

* Image recognition.

* Language understanding.

* Complex pattern recognition.

Many modern Large Language Models are built using deep learning.

### 4\. What is Generative AI?

Generative AI is a category of AI that creates new content based on patterns learned from training data.

It can generate:

* Text.

* Images.

* Audio.

* Video.

* Computer code.

* Structured data.

Examples include:

* ChatGPT generating answers.

* AI generating Python code.

* AI summarizing financial reports.

* AI drafting investment research summaries.

| Traditional ML                                | Generative AI                                             |
| --------------------------------------------- | --------------------------------------------------------- |
| Primarily predicts or classifies              | Generates new content                                     |
| Often trained for a specific task             | Foundation models can support many tasks                  |

| Example: Predict portfolio value              | Example: Summarize portfolio performance                  |

Important: Generative AI does not replace traditional ML. Both can be used together in enterprise applications.

### 2\. What is a Foundation Model?

A Foundation Model is a model trained on broad datasets that can be adapted or prompted to perform multiple downstream tasks.

Think of it as a general-purpose AI engine.

For example, one foundation model may be used for:

* Summarizing financial documents.

* Answering questions.

* Extracting transaction details.

* Generating code.

* Classifying emails.

You don't necessarily need to train a separate model for each task.

### Foundation Model vs LLM

| Foundation Model                                       | LLM                                    |
| ------------------------------------------------------ | -------------------------------------- |
| Broad category of pretrained models                    | A foundation model focused on language |
| Can work with text, images, audio and other modalities | Primarily designed for language tasks  |
| May be multimodal                                      | May also be multimodal                 |

A multimodal model can process more than one type of input, such as text and images.

### 3\. What is Model Training?

Training is the process through which a model learns patterns from data by adjusting its internal parameters.

For example:

A language model processes a large amount of text during training.

It learns statistical relationships between words, phrases and other tokens.

The resulting model can generate language based on the patterns it learned.

### 4\. What is Inference?

Inference is the process of using an already-trained model to generate a prediction or response.

Example:

Training:

The model learns from its training data.

Inference:

You send the following question:

"What is a mutual fund?"

The model generates an answer.

### Training vs Inference

| Training                         | Inference                                  |
| -------------------------------- | ------------------------------------------ |
| Model learns from data           | Model uses what it learned                 |
| Computationally intensive        | Depends on model and request complexity    |
| Adjusts model parameters         | Normally does not change model parameters  |
| Happens during model development | Happens when users interact with the model |

Interview takeaway: When integrating GenAI into enterprise applications, you will most often consume a pretrained model through inference APIs rather than train a foundation model yourself.

### Part 3. How does ChatGPT generate answers? (10 minutes)

This is an essential concept for understanding LLMs.

Let's understand it with a simple example.

You enter:

"What is AWS Lambda?"

The model generates an answer one token at a time.

### 1\. What is a Token?

A token is a unit of text processed by a language model.

A token can represent:

* A complete word.

* Part of a word.

* A punctuation mark.

* A number or other text unit.

For example:

```text
Artificial Intelligence is useful.
```

The model may divide this sentence into multiple tokens.

Tokenization depends on the model's tokenizer. A token is not necessarily the same as a word.

![Tokens and Tokenization are an Important for Fundamental LLM Understanding | NextBigFuture.com](https://images.openai.com/static-rsc-4/jmgdTIuFq6o5qj5NkrtKl8eoltxDjfORbwf9bCf_XldyQNm_Y-Pa7VAk8lg1SP0xX34ZrdWgeJMNBSl9lepRtGTrxAIMFEuplQq1ApCgSsLZ2cWDn5Y3boPWMoOUpVZMuC42F2R9dU8TBm7ERCtq9wDPS6LgiGYjkicB7n7XtQ-SZldxkUksLzEM0eaCm01B?purpose=fullsize)

### Why are tokens important?

Tokens affect:

* Input size.

* Output size.

* Model processing limits.

* API pricing.

* Response latency.

For example, if you send a 100-page financial document to an LLM, the number of tokens may be very large.

This can increase cost and may exceed the model's context limit.

As a Technical Lead, you should understand token usage when designing high-volume enterprise AI applications.

### 2\. What is a Context Window?

A context window is the maximum amount of input and output content a model can process in a single interaction, measured in tokens.

Imagine that you ask an LLM to summarize a 500-page investment management document.

If the document exceeds the model's available context window, you cannot simply send the entire document in one request.

You may need:

* Document splitting.

* Chunking.

* Summarization.

* Retrieval-Augmented Generation (RAG).

We will study RAG in a future lesson.

Important: A larger context window does not automatically mean the model will use every piece of information equally well.

### 3\. How does an LLM generate the next token?

An LLM generally generates text by estimating probabilities for possible next tokens based on the preceding context.

Example:

Prompt:

```text
The capital of India is
```

The model estimates possible next tokens.

Illustrative probabilities:

| Possible next token | Probability |
| ------------------- | ----------- |
| New                 | 90%         |
| Mumbai              | 5%          |
| Bangalore           | 3%          |
| Other               | 2%          |

These values are hypothetical and are only meant to explain the concept.

The model selects a token according to its decoding strategy and continues generating the response.

For example:

```text
The capital of India is New Delhi.
```

It repeats this process until it reaches a stopping condition or output limit.

### 4\. What is a Transformer?

A Transformer is a neural network architecture that is fundamental to many modern LLMs.

It uses a mechanism called Attention.

### What is Attention?

Attention allows a model to weigh the relevance of different parts of the input when processing information.

Example:

"The portfolio manager sent an order to purchase 500 shares. The manager confirmed it yesterday."

The model needs to understand what "it" refers to.

Attention mechanisms help the model use relevant context when processing the sentence.

We will explore Transformer architecture, self-attention and positional information in more detail in Day 9.

### Part 4. Five important GenAI concepts (10 minutes)

### 1\. What is Prompt Engineering?

Prompt Engineering is the practice of designing instructions and providing context to guide an LLM toward a useful output.

Example:

Weak prompt:

```text
Read this email.
```

Better prompt:

```text
You are an investment operations assistant.

Read the following portfolio manager email.

Extract:
1. Portfolio ID
2. Security name
3. Buy or Sell instruction
4. Quantity

Return the result in JSON.

If information is missing, return null.

Do not invent missing values.

Email:
"Please buy 500 shares of ABC Ltd
for portfolio P1001."
```

The second prompt provides:

* Role.

* Task.

* Output format.

* Constraints.

* Source information.

We will study advanced prompting techniques in Day 10.

### 2\. What is a Hallucination?

An AI hallucination occurs when a model generates information that is incorrect, unsupported or fabricated but may sound convincing.

Example:

You ask:

"What was the portfolio's closing value yesterday?"

The model does not have access to the actual portfolio database.

It responds:

"The closing value was ₹50 lakh."

This is dangerous because the answer sounds authoritative despite lacking evidence.

### How can we reduce hallucinations?

* Supply trusted information.

* Use RAG when appropriate.

* Ask the model to identify missing information.

* Require citations or source references where supported.

* Validate outputs.

* Use deterministic business rules.

* Require human approval for consequential decisions.

Remember: Prompt instructions alone cannot guarantee that hallucinations will never occur.

### 3\. What is Fine-Tuning?

Fine-tuning means taking a pretrained model and further training it on a specialized dataset to adapt its behavior to a particular task or domain.

Example:

You want a model to consistently follow your organization's specialized financial terminology and classification patterns.

Fine-tuning may be useful if prompting and retrieval are insufficient.

However, fine-tuning is not the same as providing current business data to the model.

For frequently changing financial information, retrieving the latest trusted data is often more appropriate.

### 4\. What is an Open-Weight Model?

An open-weight model provides access to its learned model parameters under the provider's license.

This can allow organizations to run or adapt the model in their own environments.

However, open weights do not automatically mean:

* Open-source training data.

* Unlimited commercial usage.

* No licensing restrictions.

* No infrastructure costs.

* Better privacy by default.

### 5\. What is Temperature?

Temperature is a model-generation setting that influences how predictable or varied token selection is.

General behavior:

| Temperature | Typical behavior        |
| ----------- | ----------------------- |
| Low         | More predictable output |
| Medium      | Some variation          |
| High        | More diverse output     |

For financial information extraction, a lower temperature is often preferable.

For creative content generation, a higher temperature may be useful.

However, low temperature does not guarantee factual correctness or deterministic output.

### Step 5. Validate the response using deterministic Python rules

This is extremely important.

Never assume that a syntactically valid LLM response is automatically business-valid.

```python
def validate_order(order):

    if order["action"] not in ["BUY", "SELL"]:
        raise ValueError("Invalid action")

    if not isinstance(order["quantity"], int):
        raise ValueError("Quantity must be an integer")

    if order["quantity"] <= 0:
        raise ValueError("Quantity must be positive")

    if not order["portfolio_id"]:
        raise ValueError("Portfolio ID is required")

    if not order["security_name"]:
        raise ValueError("Security name is required")

    return True

if validate_order(result):
    print("Basic validation successful")
```

In a production system, also validate:

* Portfolio existence.

* Security identifier against a trusted security master.

* User authorization.

* Order limits.

* Available cash or position.

* Duplicate instructions.

* Trading restrictions.

* Approval requirements.

### Part 6. Five Technical Lead interview questions (10 minutes)

### Q1. What is the difference between Traditional Machine Learning and Generative AI?

Strong sample answer:

Traditional Machine Learning primarily focuses on learning patterns from historical data to make predictions, classifications or discover relationships.

Generative AI focuses on creating new content such as text, code, images and structured responses.

For example, in financial services, a traditional ML model can predict whether a transaction requires investigation, while a Generative AI model can summarize the transaction history and explain relevant information to an operations user.

In enterprise architecture, I would use these technologies together where appropriate rather than treating them as alternatives.

### Q2. What is an LLM, and how does it work?

Strong sample answer:

An LLM is a Large Language Model trained on large datasets to understand and generate language.

Most modern LLMs use Transformer-based neural network architectures.

They process input text as tokens and generate output by predicting subsequent tokens based on the preceding context.

They can support use cases such as summarization, question answering, information extraction and code generation.

For enterprise applications, I would consume a suitable pretrained model through a secure inference API rather than train a foundation model from scratch.

### Q3. What is the difference between Model Training and Inference?

Strong sample answer:

Training is the process of learning model parameters from data.

Inference is the process of using an already-trained model to generate predictions or responses.

In my enterprise environment, I would generally integrate pretrained foundation models through inference APIs.

This reduces the infrastructure and operational complexity associated with training large models.

I would focus on selecting an appropriate model, prompt design, data protection, latency, token costs and output validation.

### Q4. What is a hallucination in Generative AI, and how do you control it?

Strong sample answer:

A hallucination occurs when an LLM produces information that is unsupported, incorrect or fabricated.

This is a significant concern in financial applications because incorrect financial information could lead to poor decisions.

I would reduce this risk through several layers:

* Supply trusted and relevant context.

* Use RAG when access to internal knowledge is required.

* Require source references where applicable.

* Validate structured outputs against schemas.

* Apply deterministic business rules.

* Monitor output quality.

* Require human approval for consequential financial actions.

I would also clearly distinguish between AI-generated recommendations and verified financial data.

### Q5. What is the difference between Prompt Engineering and Fine-Tuning?

Strong sample answer:

Prompt Engineering involves designing instructions, context and output constraints to guide an existing model.

Fine-Tuning involves additional training of a pretrained model using specialized data to adapt its behavior.

I would begin with prompt engineering because it is generally faster and less operationally complex.

If the application requires specialized behavior that cannot be achieved sufficiently through prompting and retrieval, I would evaluate fine-tuning.

For frequently changing business information, I would generally prefer retrieving the latest trusted data rather than relying on model fine-tuning.

### Scenario: Management wants to introduce Generative AI into Apollo

Your organization currently processes portfolio manager emails using Python Lambda and Microsoft Graph API.

The extracted investment instructions are transformed into JSON and passed to a .NET 8 REST API.

The organization wants to introduce Generative AI to improve email understanding and information extraction.

### Interview question

As a Technical Lead, how would you introduce Generative AI into the existing application without affecting the reliability of financial order processing?

### Strong sample answer

I would introduce Generative AI as an additional intelligence layer rather than replacing the existing enterprise transaction-processing architecture.

First, I would identify the specific business problems.

These may include:

* Extracting structured information from unstructured emails.

* Identifying missing order information.

* Summarizing portfolio manager instructions.

* Classifying different types of investment requests.

I would evaluate an appropriate foundation model, such as one available through Amazon Bedrock.

### Proposed architecture

The processing flow would be:

* Microsoft Graph retrieves incoming emails.

* AWS Lambda processes email content and attachments.

* The application constructs a controlled prompt.

* A foundation model generates structured JSON.

* Python validates the response format.

* The .NET 8 API performs deterministic business validation.

* Valid instructions are presented in React for authorized human review.

* Approved instructions enter the existing order-processing workflow.

### Key architectural decisions

1\. Model selection

I would compare candidate foundation models based on extraction quality, latency, cost, supported languages and data governance requirements.

2\. Security

I would use IAM roles, least-privilege permissions, encryption and secure configuration.

3\. Prompt injection protection

Email content must be treated as untrusted data. A malicious email must not be allowed to override system instructions or cause unauthorized tool execution.

4\. Deterministic validation

The model can extract an order, but the .NET application must independently verify portfolio identifiers, security identifiers, quantities, permissions and trading restrictions.

5\. Human approval

The AI model must not independently execute financial orders. Authorized users must approve consequential transactions under the organization's controls.

6\. Scalability

I would use asynchronous processing, queues where appropriate, retries, dead-letter handling and idempotency to support high-volume workloads.

7\. Observability

I would monitor:

* Model response time.

* Token consumption.

* Extraction success rate.

* Invalid JSON responses.

* Business validation failures.

* Model errors.

* Cost per processed email.

8\. Rollout strategy

I would begin with a controlled pilot or shadow mode.

We would compare the extracted data against existing processing results and human-reviewed outcomes.

After meeting agreed acceptance criteria, we could progressively enable the new workflow.

### Strong closing statement

"My architecture principle would be to use Generative AI for understanding unstructured information while keeping financial calculations, business validations, authorization and transaction execution within deterministic enterprise services."

Technical Lead answer
